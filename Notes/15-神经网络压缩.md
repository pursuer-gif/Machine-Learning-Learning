# 听课笔记15：神经网络压缩

## 一、为什么要压缩

- 在一些特定的情境下（比如智能手表之类的地方），大模型带不动，参数要小
- 为什么不传输到云端呢？因为数据传输可能会花费一些时间，可能不能很好地完成任务
- 为什么不直接训练小模型呢？因为**大的神经网络比较容易训练**
  - 猜想：大的网络可以看成很多小的网络的集合——训练网络不是那么容易成功的，如果有一个小的网络成功了，整个网络的效果都会变好，这种情况下小的网络越多就越容易成功
  - 这或许和每个神经元的初始化参数有关？有一些参数是可以训练起来的，有一些不可以
- 参数的关键是**正负号，绝对值不重要**——如果正负号是对的就可以训练出来（并不一定就是真理）

## 二、Network Pruning（网络剪枝）

- 有一些参数可能没怎么做事，就需要去掉，腾出空间——而且准确率不会掉太多
- 剪枝流程：剪掉 → 微调 → 再次评估 → 再去掉
- **Weight pruning（权重剪枝）**：按参数来修剪——修剪完之后形状可能变得不规则，不好实做，也不好用 GPU 加速计算；可能虽然参数少了，但是计算速度没有变好，准确率反而低了
- **Neuron pruning（神经元剪枝）**：按神经元来修剪——效果会更好

## 三、Knowledge Distillation（知识蒸馏）

### 基础：Teacher 教 Student

- 也可以让一个 teacher Net 来教一个小的 Student Net
- 给老师网络一个输入，输出结果；给学生同样的输入，让输出逼近老师的答案
- **机器的逻辑可能比人的逻辑更能教机器**——用 cross-entropy 来逼近
- ensemble：让多个机器输出的结果平均，把这个平均的结果当做最终的输出
- 但这样网络太多了，不适合实际——可以把 ensemble 的输出当做 teacher Net，让它的输入和输出去训练一个新的模型
- 加温度的 softmax（softmax(z/T)，T>1）可以让原来比较集中的分类分数变得比较平滑（软化）——普通 softmax 反而可能很尖锐
- 补充（为什么软标签更好）：老师的输出是软标签，比 one-hot 硬标签信息更多——硬标签只有"这是猫"，软标签还包含"有点像狗、不太像桌子"的类间相似性知识，学生能举一反三

### 温度 T 对输出的影响

- T = 1：普通 softmax；T > 1：分布变平滑（软，接近均匀）；T < 1：变尖锐（硬，接近 one-hot）
- 例子：分数 [10, 9, 0]（猫、狗、桌子）——T=1 时 [0.73, 0.27, ~0]，桌子被压没；T=5 时 [0.46, 0.38, 0.16]，"猫狗近、桌子远"的类间关系浮现
- 名字来源：借自物理的玻尔兹曼分布 P ∝ e^(−E/kT)——温度越高分布越均匀，越低越集中
- 用法：训练学生时老师用高温（如 T=4）输出软标签；部署时学生用 T=1 正常预测

### 进阶：逐层蒸馏（Layer-wise Distillation / FitNets）

- 普通蒸馏只学老师的最终输出；逐层蒸馏让学生的每一层都逼近老师对应层的输出（中间表示）——老师把每层的"解题草稿"都给学生看
- 为什么有用：中间监督（每层都有梯度目标，训练更容易，尤其学生更深更窄时）；学到"逐步抽象"的过程
- 难点：学生和老师的维度/层数往往不同——需要映射层（1×1 conv 或线性变换）对齐维度；也可以只挑关键层匹配
- 通常和输出蒸馏结合：总损失 = 输出蒸馏损失 + 各层匹配损失
- 变体：Attention Transfer（注意力迁移）——不匹配特征图，匹配"注意力图"（空间重要程度分布），更轻量

## 四、Parameter Quantization（参数量化）

- 用更少的 bit 去存一个数值——因为可能不用那么精确
- 也可以加入哈夫曼编码的应用：常出现的用更精确的，其他的就不用那么精确
- Binary Weights：也许可以让参数只有正负 1

## 五、Architecture Design（框架设计）

### Depthwise + Pointwise（depthwise separable convolution，深度可分离卷积）

- **depthwise convolution**：每一个 channel 对应每一个 filter——但这样 channel 和 channel 之间就没有互动了，如果有什么需要多个 channel 联合才能看出来的就没法实现了
- **pointwise convolution**：强制每一个 filter 是 1×1——只考虑不同 channel 之间的参数，因为同一个 channel 内部的关系由 depthwise 考虑完了
- 原理：low rank approximation——可以把一层网络拆成两层网络，如果中间层的参数比较少，那么整个网络的参数就会减少
- 图示（输入 3 channel → 输出 2 channel）：
```
【传统卷积】                          【深度可分离卷积】
 输入 H×W×3（3个channel）             输入 H×W×3
   ↓ 3×3×3 卷积核 × 2 个               ↓ ① depthwise：每个 channel 各配一个 3×3 核
 输出 H'×W'×2                        （只看空间，channel 间不互动）
 （空间 + channel 同时处理）           输出 H×W×3（channel 间无交流）
                                      ↓ ② pointwise：1×1 卷积
                                     （只看 channel，把各 channel 加权综合）
                                     输出 H×W×2
```
- 参数对比：传统 = 2×3×3×3 = 54；深度可分离 = 3×3×3（depthwise）+ 2×1×1×3（pointwise）= 27 + 6 = 33——参数减少
- 原理（low rank）：把"空间+通道"耦合的大操作，拆成"空间"（depthwise）和"通道"（pointwise）两个小操作——就是矩阵低秩分解的卷积版

## 六、Dynamic Computation（动态计算）

- network 可以根据运算的需求调用不同的算力，也可能是通过同一个设备的不同状态来调整运算需求
- 可以把每一个额外的层接出来，然后每一层的输出和最终的标准求差，最小化所有差的和——不过这种方法不是最好的，存在一些问题
- 还有 **Dynamic Width**：可以自由调整网络调用的宽度
- 有没有办法让网络自行根据环境去调整宽度和深度呢？
