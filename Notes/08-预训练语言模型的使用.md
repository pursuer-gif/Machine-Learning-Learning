# 听课笔记8：如何有效使用预训练语言模型

## 一、预训练语言模型

- pre-trained Language models：判断哪个句子出现的几率更大
- 怎么训练的？给一个不完整的句子，让他预测剩下的部分，类似 BERT？
- **自回归语言模型（Autoregressive Language Model）**：
  - 输出下一个字的概率分布
  - 不一定是概率最大的被 sample 出来，也可能采样到概率小的（掷骰子？）
  - 结构：embedding layer → 很多层 transformer → 最后一层用 language model Head
  - **LM Head** = 词表上的分类器（和分类头同构，只是类别数 = 词表大小几万个）：最后一层的向量 → 线性层 → 词表大小个分数 → softmax → 输出"下一个字/填空字"的概率分布

## 二、微调（Fine-tuning）

- 例：判断影评的态度——把最后的 LM Head（预测下一个字是什么）丢掉，改成 classifier Head 输出态度
- 换头不换身：骨干参数保留（这就是预训练的价值），LM Head 只服务于预训练，下游任务换上新的任务头

## 三、预训练模型的两大问题

- **Data scarcity**：数据不够
- **参数太大**：比较浪费空间、时间花费久

## 四、方案一：数据少 → Prompt tuning

### 原理：把任务伪装成填空

- 举例：两个句子（前提和假设），判断两者之间的关系
- 本质 = 不改（或少改）模型参数，改写输入，把任务伪装成预训练模型本来就会的填空
- 三步：
  1. **模板 template**：premise ?[mask] hypothesis——把任务改写成带 [MASK] 的填空
  2. **LM Head 填空**：BERT + LM Head 输出词表上每个词的概率
  3. **Verbalizer** 把标签转换为想要的输出：把词翻译回标签（yes→蕴含、no→矛盾、maybe→中立；各标签对应词的概率相加比大小）
- 为什么用：数据少（全量微调易过拟合）+ 参数大（微调成本高）

### 对比标准微调

| | 标准微调 standard fine-tuning | Prompt tuning |
| --- | --- | --- |
| 输入 | premise sep hypothesis | premise ?[mask] hypothesis |
| 输出头 | classifier Head（新学） | 复用 LM Head |
| 改动 | 改全部参数 + 换头 | 参数基本不动 + 改写输入 |

- 数据较少时 prompt tuning 效果好；数据量大时两者没什么差别

### 两种形式

- **硬提示（Hard prompt）**：手写模板，参数完全不动（in-context learning 是极端形式）
- **软提示（Soft prompt）**：提示是一串可学习向量，只训练提示参数、模型冻结

### 进阶方法

- **LM-BFF**：better few-shot fine-tune of language models
  - prompt + demonstration：few-shot（示例极少）场景——模板 + 自动挑选的示例，让模型先看几个例子再填空
- **Pattern-Exploit Training（PET）**：
  - 补充：用模板让 LM 填空，把填词结果当作伪标签来训练/蒸馏一个小模型——和下面的半监督伪标签思路相关
- **Semi-supervised Learning 半监督学习**：
  - 用少量的标注数据 + 大量的未标注数据来训练
  - 需要 prompt tune 的模型来标注；用不同的模型标注综合考虑
  - 补充：本质 = 伪标签——先用少量标注数据训练模型，再让模型给大量未标注数据打标签，扩充训练集；"不同模型标注综合考虑" = 多模型投票，减少错误标签
- **Zero-shot learning**：
  - 1 task description（任务描述） 2 prompt（直接问，不给示例）

## 五、方案二：参数太大 → 参数高效微调（Parameter-efficient Fine-tuning）

- 核心思路：想办法降低微调时更新的参数量
- 传统方法：distillation 蒸馏、pruning 剪枝
- 可以让 transformer 的参数共享（这样不会有问题吗？）
- 多任务：共用一个 BERT，给不同的任务配不同的输出头
- 目标：需要训练的百分比 percent trainable 分别小于 5% / 1% / 1% / 0.5%

### 1. Adapter（适配器）

- 结构：multi-head → **Adapter** → Add&Norm → feed-forward → **Adapter** → Add&Norm（每个子层之后各插一个）
- 补充 Adapter 内部结构：**down-project（降维，如 768→64）→ 非线性 → up-project（升维回 768）**
  - 瓶颈结构：中间维度远小于输入/输出维度 → 参数极少
  - 训练时只更新 Adapter 的参数（约 3%~5%），原模型冻结

### 补充：前馈神经网络 FFN（feed-forward network）

- 结构（即下面的公式）：**up-project（升维，768→3072，约 4 倍）→ Nonlinearity（GELU/ReLU）→ down-project（降维回 768）**
- 本质：一个最简单的 MLP，Transformer 中每个 token 的向量独立过一遍
- 作用：注意力负责 token 之间的信息交换，FFN 负责单个 token 内部的特征加工（非线性变换）
- 为什么先升维再降维：在高维空间展开做变换，更容易把有用特征分离出来，再压回原维度

### 2. LoRA（Low-Rank Adaptation，低秩适配）

- 加在权重矩阵上（笔记：加在前馈神经网络那一层；实际常用在注意力 Q/K/V/O 投影，也可加 FFN）
- 补充思想：微调时的参数更新量 ΔW 是低秩的，可以用两个小矩阵近似：
  - **W' = W + BA**：A 负责降维（r×d），B 负责升维（d×r），r 很小（如 8）
  - A 随机初始化、B 零初始化（保证一开始 W+BA = W，不破坏预训练成果）
  - 训练只更新 A、B：参数量从 d×d 降到 2×d×r（约 1% 以下）
  - 推理时可合并回 W'，零额外计算开销
- 和 Adapter 的区别（"应该是和 Adapter 类似的？"——对，同一类思路，但实现不同）：
  - Adapter：串行插入新模块 → 网络变深，推理有额外计算
  - LoRA：并行低秩分支 → 网络结构不变，可合并回原权重

### 3. Prefix tuning（前缀微调）

- 在原本的自注意力机制之前插入一些东西，它们没有 q，只有 k 和 v
- 做自注意力时把这些前缀也考虑进去
- 只更新这些前缀的 k 和 v，减少训练参数

### 4. Soft prompting（软提示）

- 只插入在 embedding layer 后面，只微调训练插入的部分
- Soft 可以是任意的向量（在原本向量空间里的），可以梯度下降；Hard 只能是原本词汇里的词，词汇是离散的、不可以单独梯度下降，所以整个模型的框架都要调整

### 参数高效微调的好处

- 减少过拟合
- better out-of-domain performance（域外泛化更好）
- 可以在较小的数据集上训练

### Early Exit（早退）

- 在每一层的后面都加上 classifier head，自行判断在哪一层训练得差不多了（提前退出）
- 补充：推理时简单的样本在浅层就能判断，省去后面层的计算
